### Joined managed capture and recovery fixture

The native fork CI job exercises [ordinary capture enrollment](03b-managed-capture-binding.md)
and the [durable send/recovery driver](04a-publisher-recovery.md) in one workflow.
Use the opt-in extension upgrade and a low-privilege PostgreSQL writer. Source
the claim members from ordinary SQL-generated segment IDs and payloads. Observe
zero foreground catalog requests. Test both immediate termination after remote
acceptance and a returned ambiguous failure. On recovery require one original
commit POST, one WAL-flushed intent with the original bytes, exact independent
rows at both pins, and an unaffected later segment. Replaying a completed
operation preserves the receipt and issues zero catalog requests.

Purpose-specific credentials are a dependency of the native scheduler. Before provider I/O refuse a valid bundle for a sibling binding or the wrong purpose, and refuse expired credentials. The recorder distinguishes catalog bearer purpose, SigV4 key and session-token headers, object writes and catalog POSTs. Repeat on a real scoped issuer before publishing a cloud profile. [Credential handoff](04b-scoped-send-admission.md#credential-handoff)

Before provider preparation, qualify the typed ledger adapter. With an out-of-line payload, both the row and logical byte budgets must refuse just below their exact totals. A stale owner and a reserved attempt must refuse source reads. Use original retained proposal bytes after revocation, source removal and restart. Observe zero catalog requests on overbudget, stale-binding, and wrong-mode dispatch controls. Race a new retained attempt against an admitted send hint and require rediscovery before any provider work. [Bounded ledger adapter](04b-scoped-send-admission.md#bounded-ledger-adapter)

A separate lookup-only wake on an unsent operation must leave the owner generation unchanged and issue zero catalog requests. Withhold PostgreSQL's success reply after its real authorization commit and restart. Observe **zero catalog commit POSTs**, the original source and intent WAL commits, identical retained bytes, the reserved first member, the later pending member and Trino's unchanged parent. The joined fixture exercises these checks with the Rust driver. The opt-in native lookup preflight verifies the local retained ledger across PostgreSQL restart with its dedicated SQL role. The opt-in 1.12 worker replays these restart faults using the real provider and a separately approved lookup mapping. Race another owner during the GET and require stale finalization to leave zero published flips. The 1.13 hold test separately proves a PostgreSQL-native top-level authorization commit, including lost acknowledgement and no provider traffic. Keep the hosted issuer, scheduler and one-use native submit gates separate. [Worker contract](04b-scoped-send-admission.md#native-worker-integration)

The fixture trusts a disposable operator's explicit enrollment facts. Extension 1.8 validates member scope and checks the active grant at the send fence in the joined fixture. Production enablement still requires the native scheduler, actual credential resolution and a deployment-specific zero-forbidden-request drill. The managed read overlay and promoted-primary
recovery each need their own release gate.

**Safe parallel starts.** Stock packaging, scoped cloud reads, ledger enrollment and independent exact-row fixtures may start against the shared contract. Integrate the actual writer only after verified capture and local send durability. Enable managed reads only after membership and real worker receipts. Service routing may consume pinned reads independently of managed capture. Serialize SQL upgrade numbers, shared ABI/header exports and fixture semantic changes. Freeze a digest for each set of vectors; provider and consumer must pass the same digest before claiming integration.
